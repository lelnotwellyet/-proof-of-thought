PROOF OF THOUGHT

Decentralized Intellectual Property & Cryptographic Content Verification System

Project Scope: A production-grade Solana Mobile dApp (React Native 0.83 / Expo 55) integrating Rust/Anchor smart contracts, Metaplex Digital Asset Standard NFTs, and SHA-256 tamper-evident IPFS storage.

1. Executive Summary & Problem Statement

In traditional social platforms and digital note-taking apps, content timestamping and author attribution are managed by centralized servers that can alter records, censor posts, or shut down. Proof of Thought solves this by allowing users to capture ideas (via formatted text or raw voice memos), publish them to decentralized storage (IPFS), and mint an immutable on-chain certificate of ownership on the Solana blockchain.

Unlike conventional NFT projects that simply point a token to an off-chain URL, our architecture introduces an Anchor On-Chain Registry. Every thought is cryptographically hashed with SHA-256 and committed to a Program Derived Address (PDA) on-chain. This provides mathematical, mathematically tamper-evident proof that a specific piece of text or audio existed at a specific slot timestamp under the author's public key.

3. System Architecture & Dual-Layer Verification

The app executes a dual-layer on-chain flow to ensure complete authenticity without expensive blockchain storage bloat:

  |  1. Text Input (max 280 chars) OR Voice Recording (.m4a via expo-audio)        |

  +---------------------------------------------------------------------------------+
  |                       OFF-CHAIN IPFS STORAGE (PINATA)                           |
  |  • Stores raw .m4a audio file & metadata JSON: { thought, author, timestamp }   |
  |  • Returns immutable Content Identifier (CID) Gateway URI                       |
  +---------------------------------------+-----------------------------------------+
                                          |
                        Mint NFT via MWA  |  (Phantom Signs Tx)
                                          v
  +---------------------------------------------------------------------------------+
  |                         SOLANA DEVNET BLOCKCHAIN                                |
  |                                                                                 |
  |  [Layer 1: Metaplex Token Metadata]                                             |
  |  • Mints POT NFT with uri -> IPFS gateway link                                  |
  |  • Assigns on-chain ownership to User Wallet                                    |
  |                                                                                 |
  |  [Layer 2: Custom Anchor Thought Registry]                                      |
  |  • Instruction: register_thought(content_hash: [u8; 32])                         |
  |  • Derives PDA Account: seeds = ["thought", mint_pubkey]                        |
  |  • Stores: { author: Pubkey, mint: Pubkey, content_hash: [u8; 32], clock: i64 } |
  +---------------------------------------------------------------------------------+

Why not store the raw text directly in Solana account data?

  • Rent-Exemption Economics: Solana charges rent based on byte size (~0.00089 SOL per 100 bytes). Storing raw paragraphs or audio would quickly cost 0.05–0.5 SOL per thought.
  • Cryptographic Solution: By hashing the text into a fixed 32-byte SHA-256 digest ([u8; 32]), we achieve 100% tamper resistance for exactly 113 bytes of account data, costing less than $0.001.

5. Comprehensive Viva Voce Questions & Model Answers

Q1. What is a PDA (Program Derived Address) and why is it essential here?
A PDA is an address generated deterministically from seeds (b"thought" + the NFT mint public key) and the Program ID that intentionally falls off the Ed25519 elliptic curve. Because it has no private key, only our smart contract code has the authority to initialize or write to it via cross-program invocation. This guarantees no third party can forge a thought record.
Q2. What happens if someone tampers with the thought text on IPFS?
When a user opens the Thought Detail screen, the app fetches the IPFS text and computes its SHA-256 hash. It simultaneously fetches the PDA from Solana devnet and reads the stored hash. Because SHA-256 is collision-resistant, altering even a single comma changes the output digest completely, causing the verification check to fail and displaying a red [UNVERIFIED / TAMPERED] warning.
Q3. Why did you use Mobile Wallet Adapter (MWA) instead of holding a keypair in the app?
Security best practices dictate that dApps must never touch raw user private keys. MWA uses local Android Intent communication to request transaction signatures from dedicated hardware/software wallets like Phantom. The user reviews the exact simulation and fee in Phantom, approves it, and returns only the cryptographic signature to our app.
Q4. How do you query thoughts without scanning the entire blockchain?
We utilize Metaplex's Digital Asset Standard (DAS) RPC indexer (getAssetsByOwner and getAssetsByCreator). Standard Solana getProgramAccounts calls are bandwidth-heavy and rate-limited. DAS endpoints maintain off-chain indexed tables of token metadata, allowing instant filtering by symbol POT and creator address.
Q5. Explain the account data layout of your ThoughtRecord struct.
The account allocated space is exactly 113 bytes: 8 bytes for Anchor's internal account discriminator, 32 bytes for the author's public key, 32 bytes for the NFT mint address, 32 bytes for the SHA-256 digest, 8 bytes for the Unix clock timestamp (i64), and 1 byte for the PDA bump seed.
Q6. How is your APK compiled and why can't this run on Expo Go?
Our app uses low-level native Android libraries: expo-audio for hardware microphone streams, @shopify/react-native-skia which links compiled C++ Skia 2D rendering engines, and Solana MWA native intent handlers. Expo Go is an interpreted sandbox that does not include these custom native modules. We used expo prebuild and Gradle 8.13 to compile directly to an ARM64 native APK.
